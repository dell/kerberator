## Skill

`kerberator-diagnose-auth-failure` (DG-06)

- Context is `kind-kerberator`, with the `make quickstart` environment.
- `./setup.sh d1` has run. It resets to healthy, scales `deploy/kdc` to 0, restarts

## Input

> Principal svc-2001 in namespace kerberator-demo isn't Ready and can't authenticate to Kerberos. Can you figure out why?

## Expected behavior

- Runs `collect.sh` and classifies the failure as `kdc-unreachable`.
- Quotes the error: `Cannot contact any KDC for realm 'EXAMPLE.COM' while getting initial credentials`.
- Reports realm `EXAMPLE.COM` on both Principal and Tenant, and quotes
  `kdc = kdc.kerberator-demo.svc.cluster.local:88`.
- Says this is strong evidence of a network or configuration problem, without
  claiming which, unless it has read-only evidence such as `deploy/kdc` at 0 replicas.
- Lists KDC health under "Not verified" if it did not check it.
- Doesn't take `daemon_pods_ready=1/1` as healthy. The pod passes readiness only
  because an old ticket file is still there.
- Next step is a specific KDC-side check or an admin hand-off. Doesn't suggest
  rotating the keytab.

**Fail if** it blames the key or keytab, recommends a rotation, or states that the
KDC is down as confirmed with no evidence for it.
